# Deyla Telegram bot

Telegram-чат с Deyla: планы, вопросы о расписании и напоминания для пользователей, которые привязали Telegram к аккаунту Deyla.

## Возможности

- планы обычным текстом, голосовыми, аудио и файлами PDF/DOCX, в том числе сразу несколько задач (расписание учебного дня, план поездки);
- перед добавлением — черновик с кнопками «✅ Добавить», «✖️ Отмена» и «✏️ Название / 📅 Дата / 🕒 Время» (для нескольких задач — «✏️ 1», «✏️ 2»…);
- кнопки «↩️ Отменить» и «↗️ Открыть в Deyla» под созданными событиями;
- задачи без времени («купить продукты завтра») и повторяющиеся задачи («каждую пятницу в 18:00 тренировка»);
- отметка выполненных задач: `/done`, кнопка «✅ Выполнено» под напоминанием и в плане дня; `/stats` — статистика за 7 дней;
- проверка в середине дня: «Успеваете?» с предложением перенести конкретные задачи на менее загруженный день;
- вопросы о расписании («что у меня завтра?», «когда у меня стоматолог?») и короткие ответы на обычные вопросы;
- `/today`, `/tomorrow`, `/week` и клавиатура «Сегодня / Завтра / Неделя / Выполнено / Статистика / Напоминания / Помощь»;
- напоминания с кнопками «+10 мин» / «+1 час» и утренний план дня;
- `/reminders` — настройки напоминаний прямо в чате, `/unlink` — отвязать аккаунт.

## Как устроено

### Deyla в группе

Добавьте бота в группу и назначьте его администратором либо отключите Group Privacy через
`/setprivacy` у @BotFather (после смены настройки повторно добавьте бота в группу).
Участник должен зарегистрироваться в Deyla, привязать Telegram на сайте и открыть личный чат с ботом.

Примеры: `@BotUserName просканируй чат и запланируй согласованную встречу`,
`@BotUserName добавь встречу с @Anna из последних сообщений`,
`@BotUserName что у меня завтра?`. Поддерживаются также `/scan@BotUserName`,
`/dayla@BotUserName <запрос>` и ответы на сообщения бота. Ответ на сообщение коллеги с упоминанием бота
передаёт и это сообщение, даже если его нет в буфере.

Бот держит текст и подписи полученных сообщений в памяти: до 50 сообщений на тему за последний час,
до 1200 символов каждого сообщения, до 24000 символов контекста запроса, до 256 тем всего.
Темы форума и группы изолированы. После перезапуска контекст исчезает; сообщения до подключения
бота не загружаются. При удалении бота контекст группы очищается. Вложения в группах не скачиваются.
Если Telegram передаёт только команды и ответы, используйте ответ на конкретное сообщение или настройте
права выше. Для анализа нужен настроенный LLM и `ASSISTANT_AGENT=true` на backend.

Запрос выполняется от связанного аккаунта отправителя, не от упомянутого участника и не от группы.
Сообщения других участников служат данными, а не командами. Все ответы и кнопки отправляются в личный
чат, в группе остаётся уведомление. Создание и изменение встреч требуют подтверждения черновика;
явные команды о выполнении и напоминаниях сохраняют немедленное поведение. Пользовательские команды
из группы сохраняются в истории Deyla; пассивный буфер переписки не сохраняется в базе.
Backend-контракт: `POST /internal/bot/group-chat/{user_telegram_id}`, `X-Bot-Token`,
JSON `{ "text": "запрос", "context": "JSON с цитатами" }`; ответ совпадает с обычным чатом.
Backend разрешает только привязанный аккаунт и применяет обычные лимиты ассистента.

Задача команды проходит этапы «Принять» → «Начал выполнение» → «Готово». После принятия кнопка «Готово» появляется только после подтверждения начала выполнения.

При принятии задачи команды можно выбрать сегодня, завтра, послезавтра или конкретный день во встроенном календаре с переключением месяцев. Выбранный день определяется в часовом поясе исполнителя; задача без выбранного времени остаётся без времени, исходный дедлайн сохраняется. Для календаря нужен backend с полем `today` в `/internal/bot/users/{chat_id}`.

Бот не подключается к базе данных и не обращается к GigaChat. Всё это делает backend, а бот вызывает его API `/internal/bot/*` с заголовком `X-Bot-Token`. Сам бот только распознаёт голосовые сообщения и извлекает текст из документов, а также оформляет ответы.

Привязка: на сайте в «Настройки → Telegram» пользователь получает ссылку `t.me/<bot>?start=<код>`. До привязки бот показывает приветствие с инструкцией. При привязке события, созданные в старом режиме бота, переносятся в аккаунт Deyla.

## Настройка

Создайте `.env` по образцу `.env.example`:

```env
TOKEN=telegram-bot-token-from-botfather
BACKEND_URL=http://127.0.0.1:8000
BOT_API_TOKEN=same-value-as-backend
NOTIFICATION_POLL_SECONDS=20
```

`BOT_API_TOKEN` должен совпадать с `BOT_API_TOKEN` в `backend/.env`. Раз в `NOTIFICATION_POLL_SECONDS` бот забирает у backend уведомления и отправляет их.

Чтобы под ответами появилась кнопка «Открыть в Deyla», задайте на backend `PUBLIC_APP_URL` (адрес сайта, только `https://` — Telegram не принимает ссылки на localhost).

## Запуск

Вместе со всем проектом из корня репозитория:

```bash
docker compose up -d --build
```

Отдельно (backend должен быть запущен):

```bash
pip install -r requirements.txt
python -m bot.main
```

Запускайте только один экземпляр бота с одним токеном, иначе Telegram вернёт `TelegramConflictError`.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest                                                   # оформление сообщений, клавиатуры и обработчики
DAYLA_CONTRACT_URL=http://127.0.0.1:8000 pytest          # плюс проверка клиента на запущенном backend
```
